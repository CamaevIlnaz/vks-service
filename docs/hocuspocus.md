# WebSocket документов

Протокол — [Hocuspocus](https://github.com/ueberdosis/hocuspocus) 4 поверх Yjs. Это отдельный WebSocket, не Socket.IO конференций и не HTTP API. Префикс API на него не действует. Порт задаёт `COLLABORATION_PORT` (по умолчанию `1234`), слушает `0.0.0.0`.

Клиент не собирает адрес сам. Его, имя документа и токен возвращает `POST /rooms/:roomId/documents/:documentId/access`. Метод описан в Swagger.

```js
import { HocuspocusProvider } from '@hocuspocus/provider';
import * as Y from 'yjs';

const access = await fetch(
  `${api}/rooms/${roomId}/documents/${documentId}/access`,
  { method: 'POST', headers }, // Authorization или x-guest-token
).then((response) => response.json());

const doc = new Y.Doc();
const provider = new HocuspocusProvider({
  url: access.url, // ws:// или wss://
  name: access.documentName, // document:<uuid>
  token: access.token,
  document: doc,
});
```

Провайдер должен быть той же основной версии, что и сервер. Редактор Tiptap подключается к этому же `Y.Doc`. Имена общих типов выбирает редактор: сервер хранит документ целиком и схему не задаёт.

Сокет конференций для документа не нужен. Нужна открытая сессия в активной конференции этой комнаты и прикреплённый к ней документ. Как войти в конференцию — в [документации WebSocket](/websocket-docs/).

## Токен

Токен документа — отдельный JWT. Access token и гостевой токен сюда не подходят, токен документа не подходит к остальному API.

| Поле ответа    | Смысл                                                                                     |
| -------------- | ----------------------------------------------------------------------------------------- |
| `token`        | передать в `token` провайдера. Для клиента непрозрачен: роли и права в нём не проверяются |
| `documentName` | `document:` и UUID документа. Всегда одно и то же, от конференции не зависит              |
| `url`          | публичный адрес из `COLLABORATION_URL`                                                    |
| `expiresIn`    | срок токена в секундах, сейчас `300`                                                      |

Имя в подключении должно совпасть с именем из ответа. Токен, выданный другому документу, сервер отклоняет.

Истёкший токен не рвёт уже открытое соединение. Новое подключение и переподключение требуют новый `POST .../access`. Удобно передавать в провайдер функцию, которая каждый раз запрашивает токен.

Пока соединение живо, право проверяется по базе, а не по сроку JWT: завершение конференции, потеря всех сессий участника, открепление или удаление документа сокет закрывают.

## Кто может подключиться

`POST .../access` и само подключение проверяют одно и то же.

- Конференция комнаты в статусе `ACTIVE` и ещё не начала завершаться.
- Вызывающий — участник этой конференции с хотя бы одной открытой сессией. Владелец комнаты без участия в конференции документ не открывает.
- Документ прикреплён к этой конференции и не удалён. Комната не удалена.
- Гость после завершения конференции доступ теряет. Участие в прошлой встрече само по себе актуальное содержимое не открывает.

Ошибка REST — обычный ответ API. На сокете Hocuspocus код HTTP не приходит: провайдер вызывает `onAuthenticationFailed`, текст в `reason`.

| `reason`                                             | Когда                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------- |
| `Недействительный токен документа`                   | подпись, срок или audience не сошлись                         |
| `Токен выдан для другого документа`                  | `name` не совпал с токеном                                    |
| `Токен выдан для другой конференции`                 | токен от уже не активной конференции этой комнаты             |
| `Токен выдан другому участнику`                      | участник в токене не совпал с текущим                         |
| `Документ не найден`                                 | нет документа или у вызывающего нет отношения к комнате       |
| `Документ не прикреплён к конференции`               | документ комнаты есть, к этой встрече не добавлен             |
| `Для редактирования нужно участвовать в конференции` | владелец комнаты не вошёл во встречу                          |
| `Нет активного подключения к конференции`            | участник есть, открытых сессий нет                            |
| `Для редактирования нужна активная конференция`      | пользователь уже был на встречах комнаты, активной сейчас нет |
| `Конференция завершена`                              | гость уже был на встрече этой комнаты                         |
| `Конференция завершается`                            | встречу уже начали закрывать                                  |
| `Редактирование недоступно`                          | сокет уже отозван, пришло следующее сообщение                 |

Если у вызывающего нет отношения к комнате, причина тоже «Документ не найден».

## Содержимое и курсоры

Правки — обычные обновления Yjs. Сервер рассылает их другим подключениям того же `documentName` и сам записывает состояние в PostgreSQL. Отдельного метода «сохранить» нет. Запись идёт с паузой около 2 секунд и не реже чем раз в 10 секунд, пока правки продолжаются.

Переподключение с тем же именем подтягивает документ из памяти сервера или из базы. Конкурирующие правки сходятся через CRDT. Исторических копий по конференциям нет: следующая встреча той же комнаты продолжает тот же документ.

Курсоры и присутствие передаются Awareness. Сервер поля не задаёт и как правку их не считает: время редактирования в конференции от курсора не меняется. Состояние Awareness живёт только вместе с сокетом.

## Когда сервер закрывает сокет

- Конференция завершается: вручную, по таймеру пустой комнаты или вместе с удалением комнаты. Уже принятые правки сохраняются. Новый токен этой конференции не выдаётся.
- У участника не осталось открытых сессий: выход, удаление участника или отзыв авторизации. Другие его устройства с живой сессией остаются.
- Документ открепили от конференции или логически удалили.

Документ при этом не блокируется навсегда. На следующей активной конференции его снова прикрепляют и открывают с новым токеном.

## Порядок на клиенте

1. Войти в конференцию и держать сессию открытой.
2. Убедиться, что документ прикреплён к этой конференции.
3. Запросить `POST /rooms/:roomId/documents/:documentId/access`.
4. Подключить провайдер с `url`, `documentName` и `token` из ответа.
5. На `onAuthenticationFailed` тот же токен не повторять: обновить сессию конференции или дождаться, пока документ прикрепят.
6. После обрыва связи запросить новый токен и подключиться снова с тем же `documentName`.
7. После `conference:ended` редактор закрыть. Список документов встречи остаётся в REST, содержимое по старому токену больше не открывается.
